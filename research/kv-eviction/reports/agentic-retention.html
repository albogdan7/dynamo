Agentic KV retention

When agent sessions pause between requests, does a retention policy that predicts each session's return reduce simulated request latency versus LRU, and how much headroom does an oracle show?

Simulation, not GPU measurement: complete AgentX (393 plays) on one vLLM-style worker with uncalibrated polynomial timing; cache 1,835,008 tokens (Qwen2.5-7B-Instruct-1M on one H200 SXM 141 GB); 64 sequences and 8,192 tokens per step; closed loop with 8, 32, 128 concurrent plays. Retention is a soft eviction priority and never blocks admission. Run 2026-10-30-18-02-25.

Decision (evaluation split, frozen rule)

limited demonstrated headroom for this retention interface. Rule: a non-oracle policy cuts mean request latency by ≥ 5% versus LRU, or the oracle by ≥ 10%, at ≥ 2 of 3 load levels. Met by a real policy at 0 level(s); by the oracle at 0.

last-gap (callback parity source)
class EvictionPolicy:
    def __init__(self):
        self.last_completion = {}
        self.last_gap = {}

    def on_pause(self, pause: dict):
        session = pause["session_id"]
        previous = self.last_completion.get(session)
        if previous is not None and pause["arrival_ms"] - previous >= 0:
            self.last_gap[session] = pause["arrival_ms"] - previous
        self.last_completion[session] = pause["now_ms"]
        gap = self.last_gap.get(session)
        return None if gap is None else pause["now_ms"] + gap
