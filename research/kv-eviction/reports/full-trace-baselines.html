Full-trace KV eviction baselines

How much do common eviction heuristics change KV-cache effectiveness, and through it simulated TTFT and ITL, on complete public workloads replayed with their original timestamps?

Simulation, not GPU measurement: one vLLM-style worker with the pinned engine's uncalibrated polynomial timing (max 32 sequences, 4,096 batched tokens per step, 512-token blocks). SLO: TTFT ≤ 1,000 ms and per-request p95 ITL ≤ 50 ms. No arrival scaling, load sweep, tuning or agent calls. Run 2026-10-30-12-14-44; 26 audited replays. Blocked before replay: AgentX, FreeInference (see coverage).

Policies and checks

LRUNative inactive-queue head: the least recently released eligible block.native engine implementation
FIFOAllocation-order FIFO: evict the oldest physical copy, rather than the oldest cache publication.
source
class EvictionPolicy:
    def select_victim(self, blocks: list[dict]) -> int:
        return min(blocks, key=lambda block: block["creation_order"])["block_id"]
MRUEvict the newest eligible copy in the native inactive release queue; the opposite end from LRU.
source
class EvictionPolicy:
    def select_victim(self, blocks: list[dict]) -> int:
        return min(blocks, key=lambda block: -block["lru_rank"])["block_id"]
LFULeast physical-copy accesses, then native LRU. Initial computed use counts once; each committed cached-prefix activation adds one, including overlapping readers. Canceled reservations do not count. Counts reset on reallocation.
source
class EvictionPolicy:
    def select_victim(self, blocks: list[dict]) -> int:
        return min(blocks, key=lambda block: (block["hit_count"], block["lru_rank"]))["block_id"]
SLRUSGLang-style segmented LRU: copies with at least two actual accesses are protected behind the probationary tier; native LRU within each tier. This is the two-tier hit-threshold variant, not a bounded protected queue.
source
class EvictionPolicy:
    def select_victim(self, blocks: list[dict]) -> int:
        return min(blocks, key=lambda block: (block["hit_count"] >= 2, block["lru_rank"]))["block_id"]

Definitions

  • Columns compare heuristics on identical inputs; changes are versus LRU on the same trace: relative % for counts and times, percentage points (pp) for rates and shares. Green marks the best displayed value of an outcome metric; ties and all-equal rows are unmarked. Occupancy rows are diagnostics, not rankings.
  • TTFT includes queueing. ITL pools every consecutive output-token gap; percentiles are nearest rank. One-token outputs have no ITL criterion; zero-output requests are not SLO-eligible. Goodput divides SLO passes by the span from first arrival to last terminal event, including drain.
  • Hit rate counts input tokens reused at first admission; recomputed tokens include repeated prefill after preemption. Evictions count 512-token blocks.
  • KV occupancy comes from native simulated-time telemetry every 100 ms, duration-weighted with sample-and-hold. Physical = active + inactive (reclaimable) blocks; active = referenced or reserved. Peaks and threshold times are sampled estimates. Request-active intervals start with at least one request in the system. A physically full cache of reclaimable blocks is not active-memory pressure.
  • Random seeds 0, 1 and 2 are separate runs; none is selected or averaged. Deterministic repeats show reproducibility, not statistical independence.
